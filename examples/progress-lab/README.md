# 进度计算练习

场景：项目看板根据“已完成任务数 / 总任务数”显示进度。列表为空时，旧代码返回 `NaN`，界面便可能显示 `NaN%`。

这是刻意留有 Bug 的教学代码。`progress.cjs` 是待修复文件，`progress.test.cjs` 是行为检查，不需要安装 npm 依赖。

## 开始

把这个目录复制到你自己的练习位置，先用 `node --version` 确认 Node.js 可用，再在该目录的终端运行：

```bash
node progress.test.cjs
```

第一次会在空列表检查处报 `AssertionError`，实际值为 `NaN`，期望值为 `0`。文件路径和报错行号会随环境变化。

使用 Codex App 跟练 Review 时，还需要 Git 和一份本地初始提交，具体步骤见 [CX-02 的练习准备](../../docs/codex/CX-02-Codex-App桌面工作流完整指南.md#把练习目录交给-app)。先在原代码上保存起点，再让 App 修复，才能看清差异；无需创建远程仓库。

## 这次要满足的规则

输入是非负整数，且已完成数不超过总数。这次只处理这些输入，不增加页面、网络请求或新的依赖。

| 已完成 | 总数 | 百分比 |
|---:|---:|---:|
| 2 | 4 | 50 |
| 0 | 0 | 0 |
| 4 | 4 | 100 |
| 1 | 3 | 33 |

让你选用的编程助手解释失败原因，修复 `progress.cjs`，再运行同一条命令。测试通过后输出 `progress checks passed`，并且进程正常结束。不要删除空列表检查，也不要把所有返回值都写成 `0`。

想多练一步：自己补上“完成 3 项、共 8 项”的检查。先算出应为 `38`，再让工具运行；这样能知道它是否保留了四舍五入规则。
